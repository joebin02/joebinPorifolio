- [ ] Keep resume metrics (60+ APIs, 25+ Angular modules, 90+ defects, 3 releases, 15-member team) only if cleared for public sharing
- [ ] Confirm whether the insurance domain can be named; client identity and confidential details are intentionally omitted
- [ ] Add your GitHub username and profile URL

- [ ] Add a demo link or screenshots only when they are yours to share

## Review for accuracy and confidentiality

- [ ] Every technology listed was used or is clearly labeled as learning/foundational
- [ ] All counts and role descriptions match the resume and are safe to disclose
- [ ] No TCS/client source code, internal names, screenshots, data, endpoints, or credentials
- [ ] Setup steps work from a clean checkout
- [ ] Project repositories have meaningful descriptions and READMEs
- [ ] If using this as your GitHub profile README, copy it to a public repository named exactly like your username

## Build the next portfolio project

Choose a project that demonstrates practical backend engineering, such as a REST API with validation, persistence, error handling, tests, and clear setup instructions. A small Angular client can demonstrate full-stack integration. These are suggestions for future projects, not claims about projects already completed.
